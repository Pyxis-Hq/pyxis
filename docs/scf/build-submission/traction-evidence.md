# Traction evidence

**Status:** draft for the SCF Build form, 2026-11-20. Every statement maps to [evidence/manifests/evidence-manifest.json](evidence/manifests/evidence-manifest.json). Vocabulary: Implemented, Demonstrated, Independently verified, Published, Adopted by external users, Planned.

## A. Live MVP: Implemented, Published
Pyxis runs at <https://usepyxis.xyz> with documentation at <https://docs.usepyxis.xyz>; source is public under Apache-2.0 at <https://github.com/Pyxis-Hq/pyxis>. CI is green for commit `a7df1da`; 80 automated tests pass. Created 2026-11-18; one author.

## B. Real Stellar wallet authentication: Demonstrated
On 2026-11-20 a real Varial wallet (Testnet) signed in to usepyxis.xyz: the app presented a one-time message, the wallet signed it with manual approval, and the protected projects page opened (first-run screenshots were removed because it showed unrelated browser tabs; the second run below has every prompt). A cancelled attempt left the user signed out. A live negative test with throwaway keys then confirmed the server rejects forged, altered, wrong-key, malformed, replayed and cross-account signatures (14 of 14 checks, [report](evidence/wallet/forged-signature-test.md)). Limits: challenge expiry was not tested; no HTTP logs were captured for the real sign-in. See [wallet/authentication-verification.md](evidence/wallet/authentication-verification.md). A second sign-in later the same day, in a clean browser profile with every wallet prompt approved by the user, is documented prompt by prompt in [evidence/wallet-run](evidence/wallet-run/README.md).

## D. Published wallet SDK: Published
`@pyxis-hq/wallets-kit@0.1.0-beta.1` is on npm. In the first run its browser SDK reported six funnel events; in the second run it reported a full funnel plus a **reported failure** (a rejected signing) and a disconnect. The Pyxis server stored them as counts with no address, signature or XDR. Those events are frontend-reported; only the transactions in C are ledger-verified.

## E. Real Umami analytics session: Demonstrated
A real Umami 2.20.2 instance was deployed. Pyxis verified a domain and created the Umami website itself. Two controlled internal browser sessions (7 page views on the first site, 6 on a second) produced visitors, a custom event and device and country data in Umami. See [evidence/umami/analytics-verification.md](evidence/umami/analytics-verification.md). Not external traffic.

## F. Real API ingestion: Demonstrated (internal test workload)
On 2026-11-20 a local service instrumented with the **stock OpenTelemetry Node SDK**, configured only with the settings in Pyxis' own guide (OTLP/HTTP JSON, delta temporality, an ingest key), sent 270 requests in two runs. Pyxis counted all 270, with the status classes matching the client's own counts exactly (2xx 242, 4xx 22, 5xx 6), and showed p50 92.9 ms, p95 550 ms and p99 910 ms plus a per-route table ([screenshots](evidence/api-and-web-capture/screenshots/), [report](evidence/api-and-web-capture/tested-workflows.md)). Limits: the service was built for the test and its latencies are artificial delays, so this proves ingestion and aggregation, not API performance or reliability. Route templating works with Express instrumentation; with plain Node `http` instrumentation routes appear as `/_unmatched`. A revoked ingest key was rejected on its next request (401). No external traffic.

- **Web analytics:** a second, independent session on a new verified site (`pyxis-capture-site.vercel.app`) produced 6 page views, 1 visitor, 15 s, Chrome on desktop, country NG; Pyxis matched Umami's own API ([screenshot](evidence/api-and-web-capture/screenshots/05-web-analytics.png)). The earlier session matched too ([screenshot](evidence/dashboard/screenshots/pyxis-web-analytics.png)).
- **Wallet funnel:** first run, six events once each, 0 failures (from the stored counts; its screenshot was removed because it showed unrelated browser tabs). Second run: Connect started 2, Connected 2, Sign started 2, Signed 1, Submit started 1, Submit reported OK 1, **Failures reported 1**, with the banner "Frontend-reported, not ledger-confirmed" ([screenshot](evidence/wallet-run/screenshots/15-wallet-funnel.png)); matches what the dApp did.
- **API metrics:** empty state before ingestion, 270 requests after ([before](evidence/api-and-web-capture/screenshots/02-api-dashboard-before.png), [after](evidence/api-and-web-capture/screenshots/04-api-live-metrics.png)).

## H. External adoption and pilots: none
**No external project has onboarded.** No letters of intent, pilots, customers or external users exist. The npm download count (247 on 2026-11-20) is not evidence of adoption. All runs above are internal tests.
